## English Summary

Project Overview:  
This repository contains Homework #4 for the Software Testing and QA course. The assignment demonstrates practical skills in creating, comparing, and applying core QA test documentation types: checklists, test cases, and test plans — applied to a real marketplace (Prom.ua) and a startup mobile application concept.

Key Scope & Topics Covered:

Comparative Analysis of Test Documentation: Side-by-side evaluation of three documentation types (Checklist, Test Case, Test Plan) covering key characteristics, advantages, and disadvantages for each — with focus on practical applicability from a QA Engineer's perspective.

Prom.ua Platform Testing Checklist (CHK-01 to CHK-22): A comprehensive decomposition of the Prom.ua marketplace by user roles (Buyer vs. Seller), covering header, navigation, content zone, cart, footer, seller registration, dashboard management, and finance/settings — with professional ID numbering and execution tracking columns.

CatPaw Share Test Plan: A complete test plan for a mobile photo-sharing startup (iOS & Android) including: Introduction & Objective, Scope (In/Out), Test Environment with specific devices, Team & Responsibilities, Testing Strategy (Functional, Cross-platform, Localization), measurable Entry/Exit Criteria, and Risk Mitigation strategies.

## Основні результати та практичні рішення

### 1 Порівняльний аналіз тестової документації
Проведено детальний порівняльний аналіз трьох основних типів тестової документації — чек-лісту, тест-кейсу та тест-плану — за ключовими характеристиками, перевагами та недоліками. Кожен тип оцінено з позиції практичного застосування QA-інженером: від швидкого smoke-тестування (чек-ліст) до стратегічного планування тестування проєкту (тест-план).

### 2 Чек-ліст тестування платформи Prom.ua (CHK-01 ... CHK-22)
Виконано декомпозицію маркетплейсу Prom.ua за ролями користувачів (**Покупець** vs **Продавець**), що охоплює всі ключові зони інтерфейсу: хедер, навігацію, зону контенту, кошик, футер, реєстрацію продавця, дашборд управління та фінанси/налаштування. Кожному пункту присвоєно професійний ідентифікатор (`CHK-01` ... `CHK-22`, з підпунктами `CHK-19.1`, `CHK-19.2`), що дозволяє однозначно посилатися на конкретну перевірку у баг-репортах. Передбачено 4 прогони тестування для відстеження стану виконання.

### 3 Тест-план для стартап-додатка CatPaw Share
Сформовано повноцінний тест-план для мобільного додатка обміну фото котиків (iOS & Android), що включає 7 розділів: Вступ та мета тестування, Обсяг тестування (In Scope / Out of Scope), Тестове середовище з конкретними пристроями, Команда та розподіл відповідальності, Стратегія тестування (функціональне, кросплатформне, локалізація), вимірювані критерії входу/виходу (**Entry/Exit Criteria**) та оцінка ризиків з планами мітигації.

### Враховані рекомендації та адаптація роботи:

Вимірювані критерії виходу (Exit Criteria): Додано кількісні метрики — Test Execution Rate >= 95% та Crash-free Rate > 99% — замість загальних формулювань «усі критичні баги виправлено».

Розділ тестового середовища (Test Environment): Додано окремий розділ із зазначенням конкретних моделей пристроїв (iPhone 11/14/15 Pro, Samsung Galaxy S21, Xiaomi Redmi Note 11, Google Pixel 6) та мінімальних версій ОС (iOS 15.0+, Android 10.0+).

Ризики та мітигація (Risks & Mitigation): Додано три ідентифіковані ризики (затримка Code Freeze, нестабільність API/серверів, фрагментація Android-пристроїв) із конкретними стратегіями мітигації для кожного.

## Ключові навички, продемонстровані в роботі

Тестова документація та порівняльний аналіз: Практичне розуміння того, коли і навіщо застосовувати чек-лісти, тест-кейси та тест-плани — з чіткою артикуляцією компромісів для кожного типу.

Декомпозиція за ролями (Role-Based Decomposition): Структурування тестового покриття за ролями користувачів (**Buyer** vs **Seller**), що демонструє розуміння того, що один додаток обслуговує різних користувачів із різними сценаріями — ключовий патерн QA-мислення.

Професійне написання тест-планів: Створення повноцінного, стандартизованого тест-плану з вимірюваними критеріями виходу (**Exit Criteria**), чітким обсягом тестування, оцінкою ризиків та плануванням ресурсів команди.

Тестування реальної платформи (Live Platform Testing): Практична верифікація працюючого маркетплейсу Prom.ua з деталізованими перевірками, що посилаються на реальні елементи UI та системні повідомлення.

Інтеграція фідбеку: Ітеративне вдосконалення документації на основі менторського рецензування — додавання вимірюваних метрик, специфікації середовища та аналізу ризиків для зміцнення тест-плану.
